# M3 第二批：先验证 RGB 外观门限与 Lost 恢复

本批使用同一检测缓存、同一 RGB 编码器、同一高分特征缓存。实现位于
`botsort_research/appearance.py` 和 `appearance_adapter.py`。
第二批总入口和执行顺序见本目录 README。

## 1. 本批回答什么问题

[第一批外观分层结果](../results/round1_2026-11-25/m3_appearance_strata.csv)
显示：筛选出的高分候选配对具有较强区分能力，但连续帧与较长间隔的距离分布不同。
这些配对的 AUC 不能直接证明在线恢复有效，原因包括样本筛选、轨迹特征平滑、负样本难度、在线记忆污染等。
本批用完整在线轨迹与 TrackEval 检验两件事：

1. 在同样的配对误接受预算下，按特征间隔分组的门限是否优于一个固定门限？
2. 对已经 Lost 的轨迹，显式安排一次保守的恢复机会，是否比原有竞争式关联更有效？

本批不训练新的 RGB/热红外网络，也不凭空补齐低分检测的特征。
当前缓存仅包含严格 `score > 0.5` 的 RGB 特征。低分特征提取需要单独版本的缓存、编码器校验和新的对照，作为后续条件任务。

## 2. 实验矩阵

| 变体 | 第一阶段 | unconfirmed 阶段 | 独立 Lost 恢复 |
|---|---|---|---|
| `native_reid` | 原生 IoU / 外观融合与原生 `.4` 外观门限 | 完全保留原生 `cosine/2` 与 `.4` 门限 | 无；Lost 与 active 共同参与第一阶段 |
| `reid_fixed` | 标定得到的全局原始 cosine 门限 | 将同一原始 cosine 门限除以 2 后交给原生阶段 | 无 |
| `reid_gap` | 按距上一次有效特征的间隔选门限 | 与 `reid_fixed` 相同 | 无 |
| `reid_recovery_fixed` | active 轨迹使用全局门限；旧 Lost 暂不参与 | 先处理 unconfirmed | 剩余高分候选，使用全局门限 |
| `reid_recovery` | 与上一行相同 | 与上一行相同 | 相同恢复流程，使用按间隔门限 |

`native_iou` 是无 ReID 对照；M1/M2 的改变不要同时加入此矩阵。
`reid_fixed` 对 `reid_gap` 隔离原生竞争流程中的间隔门限影响；
两个 `reid_recovery*` 对照隔离显式恢复流程中的间隔门限影响。
`reid_fixed` 对 `reid_recovery_fixed` 同时涉及阶段顺序、候选几何范围和保护记忆，
因此只能评价“显式恢复方案整体”，不能把差值全部归因于阶段顺序。

原生第一阶段使用原始余弦距离，unconfirmed 阶段使用除以 2 的距离。
标定模型保存**原始余弦距离**门限；实验变体对 unconfirmed 做相应换算。
直接把同一个数值塞入这两个阶段会产生不同的实际门限，这里明确避免该歧义。
`native_reid` 则保留冻结基线的全部原始语义，用于复现。

## 3. 离线标定协议

标定只读 `split_retrospective.json` 的 9 个 calibration 序列。
运行标定后，`model.json` 包含全局门限、4 个间隔分组门限、支持样本量、经验误接受率、回退原因和来源指纹；
`pairs.csv` 保留实际使用的配对，方便检查抽样偏差。

候选配对的具体定义如下：

- 使用当前帧检测框与 GT 的 IoU ≥ 0.5 一对一最大匹配；检测到其他 GT 的 IoU 差不足 0.05 时排除该特征归属。
- 每个 GT 身份仅保留最近一次可用高分 RGB 特征。所有当前帧特征在配对完成后才加入记忆，不产生同帧“时间配对”。
- 过去特征距当前帧为 1–30 帧，中心距离不超过原图 64 像素。
- 负样本只取 GT 类别相同的不同身份，每个观测最多选取中心最近的 5 个；类别未知的负样本排除并计数。
- 每序列、每种身份关系分别执行固定种子的 reservoir 抽样，默认上限 20,000 对。模型不据此估计正负样本先验。
- 间隔 `gap = current_frame - previous_feature_frame - 1`，分为 `0`、`1–3`、`4–10`、`11–30`。
  由于候选年龄上限是 30，实际采样最大 gap 为 29；最后一个组名保留统一的诊断习惯。

门限选择为：在经验负样本通过率不超过 `max_empirical_far=0.005` 的约束下，
取不超过 `max_threshold=0.8` 的最大可接受正样本距离。
默认每个拟合组至少需要 50 对正样本和 200 对负样本；稀疏的间隔组回退全局门限。
全局样本不足会报错；如果没有任何正样本满足误接受预算，门限保存为 `null`，表示禁用该组的外观接受证据。
它不会用一个宽松默认值悄悄放行。

该预算是**所选配对上的经验值**。输出的 Wilson 区间也只是描述性信息，
因为相邻配对共享身份、帧和录制序列，不能当作独立同分布试验的严格置信保证。
最终需要观察实际错误恢复数、IDSW、IDF1、AssA、HOTA、FP 和 FN。

## 4. 显式 Lost 恢复流程

`reid_recovery_fixed` 与 `reid_recovery` 的每帧顺序是：

1. 对原有轨迹进行一次预测和原有 SOF 相机运动补偿。
2. active 轨迹关联高分检测，再按原生 IoU 关联低分检测。
3. 原生 unconfirmed 阶段先消费其匹配到的高分检测。
4. 仅对帧开始时已经 Lost、尚未过期且有可信 RGB 记忆的轨迹，尝试恢复剩余高分检测。
5. 把恢复成功的候选从剩余列表中移除，再进入原生新轨迹初始化和状态整理。

恢复几何约束默认是原图中心距离 ≤64 像素、宽高比例均不超过 4。
外观候选必须同时满足门限、双向最近邻、行列两侧的次佳距离差均至少 0.05。
计算歧义时保留全部几何合法竞争者，包括其自身未通过外观门限的候选，避免人为降低竞争。
一个检测最多归属一个恢复轨迹，active/unconfirmed 已消费的检测不再进入恢复。

可信记忆独立于原生 EMA：仅在匹配检测分数 ≥0.6 且原图最短边 ≥4 像素时，
保存最新有效 RGB 向量；低分观测不会更新它。
本次恢复匹配不会立即覆盖其用于判断的可信向量，须等后续一次满足质量条件的正常匹配。
这是初始质量规则，尚未证明最优，配置值随实验一起记录。

恢复不延长原有 `max_time_lost`，不向历史帧补写结果，不使用在线 GT，
不恢复本帧刚刚丢失的 active 轨迹，不重新启用 Removed 轨迹。
当前冻结配置 `track_buffer=60, frame_rate=15` 对应 30 帧保留期。

**原生边缘行为说明：** 当前 BoxMOT 的状态合并顺序可能使刚标记 Removed 的对象在 lost 列表中多保留一帧。
`native_reid`、`reid_fixed`、`reid_gap` 保留原生生命周期和第一阶段候选池，以便控制比较；
显式 recovery 两组另外要求状态确实为 Lost 且年龄未超过保留期。
若后续专门修复原生生命周期，需要另列对照，不能把修复隐藏在外观门限改动里。

## 5. 特征与来源检查

重放必须提供每个序列的 `.npz` 与同名 `.json` 元数据，并通过以下检查：

- 特征元数据的检测 SHA 与当前检测缓存一致；压缩 JSON 可匹配其精确解压字节的 SHA。
- `.npz` 文件 SHA、帧编号、offset、检测索引、无重复、特征维度和有限性一致。
- 每帧特征索引必须恰好等于当前检测经 float32 转换后的 `score > 0.5` 索引，顺序一致。
- 所有高分特征必须非零且保持原始 float32，低分 dense 行只作索引占位，不参与外观证据。
- 标定记录和重放记录必须使用同一个检测器、同一个 RGB 编码器；校准输入检测、特征及元数据的指纹不可改变。
- 标定与重放序列必须属于不同的指定分区；拟合模型中的 split 必须与此次重放完全一致。

不接受通过修改元数据哈希来“修复”不匹配缓存。应提供原先配套缓存，或用同一个明确记录的编码器重新生成并建立新的实验版本。
即使 metadata 正确，零向量和缺失高分特征也会终止实验。

构造 tracker 时先运行原生 `with_reid=False` 构造路径，再为该实例启用缓存特征路径和显式报错的 CacheOnlyEncoder。
这只绕开未使用的模型加载，不改变原生匹配公式，不修改全局 ReID 类，也不下载权重。
CPU 跟踪时间仍然不包含原先 GPU 编码特征的成本。

## 6. 输出日志与错因分析

开启 `--trace` 后，实验变体输出：

- `appearance_first`：匹配轨迹、检测索引、原始 cosine、IoU 距离、实际门限、特征间隔、是否原来 Lost。
- `appearance_recovery`：成功恢复对、Lost 年龄、可信特征年龄、有效几何候选数、缺少可信记忆的轨迹数。
- 每条恢复尝试的最佳距离、行列 margin、最佳检测索引及拒绝原因：无几何候选、外观禁用、超过门限或未满足双向唯一性。
  无次佳候选时 margin 记为 `null`，不能把它解读成 0；JSON 不写入 Infinity。

重点逐项检查：

| 现象 | 优先查看 |
|---|---|
| 恢复机会很少 | 高分候选覆盖率、可信记忆缺失、几何拒绝、Lost 年龄 |
| 正确身份未接回 | 对应配对距离、实际分组门限、是否回退全局、竞争歧义 |
| 误接明显增加 | 同类近邻、双向 margin、相似外观、可信记忆是否早已被错误匹配污染 |
| 指标变好但恢复很少 | active 第一阶段或 unconfirmed 门限变化，不能把全部收益写成 Lost 恢复 |
| 长间隔门限不稳定 | 该组样本量、负样本难度、同一身份重复采样、按录制序列的差异 |

`analyze-run` 还会生成 `recovery_cases.csv` 和 `recovery_summary.csv`。
它首先校验阶段日志 SHA，再把每个 `appearance_recovery` 接受事件的
`track_id + det_index` 与本帧真正发射的输出精确连接。随后比较同一 tracker ID
**本帧之前最近一次 CLEAR 匹配的 GT 身份**与本帧输出的 CLEAR 匹配身份：

| 分类 | 含义 |
|---|---|
| `correct_same_gt` | 有历史和当前 GT 匹配，且身份相同 |
| `wrong_identity` | 有历史和当前 GT 匹配，且身份不同 |
| `current_unmatched_competition` | 历史身份已知；当前输出有 IoU ≥0.5 的 GT，但未获 CLEAR 分配 |
| `current_unlocalized` | 历史身份已知；当前输出没有达到 IoU 门限的 GT |
| `unverifiable_no_history` | 当前有输出，但该 tracker ID 尚无历史 CLEAR GT 归属 |
| `not_emitted` | 阶段日志接受了恢复，但最终输出中没有该轨迹，例如后续重复轨迹清理 |

这些类别互斥；明细还保留独立的历史可用性、当前匹配状态、特征间隔、Lost 年龄、
历史 GT 帧、当前输出 IoU 和 CLEAR IDSW，避免把无 GT、定位失败或输出被清理算成“接错身份”。
汇总按变体、序列和特征间隔分组。
`conditional_identity_precision = correct_same_gt / (correct_same_gt + wrong_identity)`
仅在历史和当前身份都可验证的子集上计算；同时报告全部接受数以及
`correct_fraction_all_acceptances`，不能隐藏未验证和未定位事件。

这里检查的是最近一次历史归属，不能证明一条轨迹从出生以来始终正确，
也不要求这次历史 GT 帧恰好等于可信 RGB 记忆的来源帧。
无阶段日志指纹时诊断状态明确记为 `SKIPPED`，不会填一个虚假的恢复次数 0；
已记录指纹而文件被修改、丢失或缺少帧时直接报错。
正式整体数值仍以同一完整输入上的 TrackEval 为准。
