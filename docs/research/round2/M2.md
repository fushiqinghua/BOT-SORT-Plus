# M2 第二轮：分离关联容差、状态更新和输出框

本轮直接承接 [第一轮定位误差归因](../results/round1_2026-11-25/mota_attribution/README.md)。第一轮的逐案例分析支持“较大的测量噪声使微小目标更新不足”这一假设，但案例经过失败条件筛选，不能把局部修复比例当作全数据集收益。本轮必须重新从第一帧在线运行，检验状态更新变化对后续关联的影响。

## 1. 三个因素分别控制

**关联协方差 `R_A`** 进入原有四维高斯负对数似然，仍保留 `logdet(S)`、高斯归一化常数、χ²/中心/尺寸门控以及显式未匹配代价。`S = H P Hᵀ + R_A`。本轮主要沿用第一轮 `floor` 的关联容差。

**更新协方差 `R_U`** 决定选定检测对状态估计的拉动。本轮 `native_update` 使用原版 `STrack` 和原版 `KalmanFilterXYWH.update`，没有用数值近似重新实现原版滤波器。`floor` 更新仍使用第一轮显式 R 和 Joseph 协方差更新。

**输出坐标** 可选 `kalman` 或 `detection`。后一种只取本帧已经选中的检测框，保留 ID、置信度、类别和检测索引；内部滤波状态继续原样传递到下一帧。不会生成未匹配输出、插值、补帧或修改轨迹历史。输出策略在 `output_policy.py` 中执行，不放进跟踪器状态更新。

当 `R_A != R_U` 时，应把 NLL 作为关联兼容性评分，把 `R_U` 作为状态更新参数。这里不再声称两个环节来自同一个完全一致的生成式噪声模型；这是根据第一轮证据提出的可检验改动。

## 3. NWD 简单对照

借用 [Wang 等人的 NWD 定义](https://arxiv.org/abs/2110.13389)；[原作者代码](https://github.com/jwwangchn/NWD)主要用于检测。这里仅把该距离作为固定检测框跟踪关联的简单对照，不声称是原论文的跟踪系统。

对于框 `(cx,cy,w,h)`，定义 `u=(cx,cy,w/2,h/2)`，代价为：

\[
c_{ij}=1-\exp(-\|u_i-u_j\|_2/C).
\]

`C` 的单位为原图像素。配置节为：

```json
{
  "nwd": {
    "normalizer_px": 12.8,
    "first_threshold": 0.8,
    "second_threshold": 0.5
  }
}
```

这是初始对照设置，不是已验证的本数据集最佳值。NWD 保留 M2 的中心距离和尺寸比物理门控，但不用 `P/R`、χ²、NLL 或额外置信度项；分配使用原版 LAP 的代价阈值规则。初始阈值相同不代表 IoU/NWD/NLL 有相同的接受范围，分析时需要同时看接受数和误关联。

## 4. 不变的实验条件

- 检测缓存、分辨率和坐标保持原版，所有检测类别仍合并为一个跟踪类别。
- M2 组使用原 SOF 相机运动补偿；与 M1 的组合实验待各自贡献明确后进行。
- 第一阶段使用严格 `score > .5`，第二阶段使用 `.1 < score < .5`；恰好 `.5` 的原版边界行为保留。
- 低置信度检测只更新尚未丢失的活动轨迹，不独立出生，不恢复已经 Lost 的轨迹。
- `track_buffer=60`、`frame_rate=15` 对应原版 30 帧 Lost 保留时间，未扩大保留时间。
- 未确认轨迹匹配、原版 `P0/Q`、共享预测、轨迹出生和删除流程不变。`iou_floor_update` 的未确认轨迹也使用 floor 更新，以覆盖整个“只变更新”对照。
- `m2_nll_floor_det` 这类输出变体由 runner 应用输出策略。直接使用 `build_tracker` 的调用者需显式调用 `apply_output_policy`，不要误以为工厂已修改输出。

边界计算沿用实际数值路径：缓存先转换为 float32，原版追加 int64 检测索引后又提升为 float64，再比较门限。因此 JSON 中的 `0.1` 转为 float32 后约为 `0.10000000149`，实际会进入低分区间；`0.5` 可被精确表示，仍被两阶段排除。诊断统计使用同一语义。

## 5. 错因记录与判读

新增关联日志在第一、第二阶段记录 `association_method`、`association_R_diag`、`update_R_diag`、更新前 `predicted_xywh`、本帧 `measurement_xywh`、检测索引、轨迹 ID 和 `was_lost`。IoU/NWD 没有关联协方差，相关字段为 JSON `null`。原生 `native_iou`、`native_iou_det`、`iou_relaxed` 不覆盖原生阶段方法，因此不生成逐候选 M2 日志。未确认匹配仍由原版处理，不包含在第一/第二阶段日志中。

应优先对比：

1. `floor` 与 `floor_det`：ID 和关联选择不变，观察纯输出定位变化。TrackEval 的 IDSW 仍可能因 IoU 匹配变化而变，不能据此声称内部 ID 产生不同。
2. `floor` 与 `floor_native_update`：变化会影响下一帧状态，必须重新在线重放，不能用离线输出替换代替。
3. `native_iou` 与 `iou_floor_update`：检验更新噪声本身是否造成负面影响。
4. 两个单阶段 NLL：确认低分第二阶段是否贡献了较多新增 FP。
5. M2 最优候选与 IoU 放宽/NWD：判断复杂概率代价是否具有超过简单距离控制的价值。

联合报告 HOTA/DetA/AssA/IDF1/MOTA、FP/FN/IDSW、各序列和尺寸分层。只看 IDSW 下降可能忽略轨迹变少带来的表面改善；只看微小 HOTA 增幅也不足以确定模块有效。原来的 21 条序列已参与错误分析，所有本轮比较均继续标为回顾性开发实验，不能重新包装成未见测试集。

## 6. 软件验证范围

`tests/test_round2_m2.py` 验证 NWD 闭式值、门控、输出不改变输入/内部状态、无效检测索引拒绝、精确原生更新、阶段隔离、未确认轨迹更新以及低分不出生/不恢复 Lost。使用冻结运行时打开集成测试：

```bash
M2_TEST_BOXMOT=1 python -m unittest discover -s tests -p 'test*2*.py' -v
```

这些测试证明实现约束；真实数据集上的指标与归因仍需本地执行第二批实验后报告。
