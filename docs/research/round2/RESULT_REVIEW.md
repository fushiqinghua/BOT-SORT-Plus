# 第二批结果判读与后续任务决策

本文件预先约定分析顺序，避免只挑一个改善的指标或序列。真实结论待实验完成后填写。

## 1. 先确认实验能比较

先看 `execution.json` 是否完整、是否省略 M3，再看原生无 ReID / RGB ReID 的逐帧复现是否通过。确认每组都是相同 evaluation 序列、相同帧数、检测、图像、GT 和固定 TrackEval；空 GT 序列必须保留。正式合并指标取 `COMBINED_SEQ`，不能把序列百分比简单平均。

`clear_verification.csv` 必须逐序列和合计通过；`summary.json` 的诊断分类只在该条件下解释。计划、源码或数据改变时，应单列另一批实验。

## 2. M2：先归因，再决定是否保留复杂关联

| 比较 | 支持该假设时预期看到什么 | 若不支持，下一步 |
|---|---|---|
| native KF vs native detection 输出 | 判断原生框输出本身是否还有收益 | 保留原输出，不把检测框输出当普遍有效规则 |
| floor KF vs floor detection 输出 | 定位相关 FP 与 FN 明显下降，源检测 / ID 选择保持一致 | 检查关联选择和原始候选，不再只归因于输出位置 |
| floor vs floor + native update | 全流程定位损失降低，同时关联收益保留 | 检查更新导致的后续预测、竞争与 P/Q 假设；避免仅靠失败样例下结论 |
| native IoU vs IoU + floor update | 在关联规则相同的前提下出现定位损失 | 若没有，考虑 R 与 NLL 选择交互，不能说 floor R 单独必然有害 |
| 第一阶段 NLL vs 第二阶段 NLL | 判断低分延续贡献了多少 FP、FN 与身份变化 | 优先保留有证据的阶段，不自动两个阶段都改 |
| M2 vs calibration 选出的 IoU / NWD | 同时审视 HOTA、DetA、AssA、IDF1、MOTA、FP/FN/IDSW 和速度 | 若简单对照相当或更好，收缩 M2，选择更简单可解释的方法 |

报告总量和逐序列得失，尤其区分 `<8`、`8–16`、`16–32`、`32+` 的变化。第一批定位异常主要来自微小目标，仍需检查大目标是否因同一修改退化。IDSW 降低可能伴随输出减少，不能单独作为身份质量改善证据。

改变输出坐标可能改变 TrackEval 的匹配，从而改变其 IDSW，即使内部轨迹 ID 没变。因此，纯输出对照的 IDSW 差值不能解释成在线换号逻辑变化。

## 3. M1：整体指标、受益序列和回退原因同时看

先比较原 SOF 与关闭 CMC，随后比较四个增量变体。至少回答：

1. HOTA / IDF1 的改善是否来自多个序列，还是被少数序列主导？
2. 原来依赖相机补偿的序列是否保持收益？原来补偿有害的片段是否改善？
3. identity fallback 比例是否过高，以至于只是近似关闭 CMC？
4. 回退发生时，是纹理不足、前景主导、前后向不一致、空间退化，还是独立留出点否定了变换？
5. 几何代理改善是否对应同帧或随后若干帧的跟踪改善？

不要按已知序列名称决定回退，也不要仅按平移幅度开关 CMC。若稳健估计已经有效，再单独设计运动估计不确定性向 P 的传播；本批不同时改预测协方差。

## 4. M3：离线配对、在线关联和实际恢复分开报告

先确认原始 RGB 特征重放与归档一致，然后看全局门限与分间隔门限的样本量、回退次数和误接受预算。分间隔对照分别在原竞争式关联与显式恢复流程内比较，避免把流程变化误算成门限收益。

逐条核对被接受的恢复事件：恢复前最近可验证的 GT 身份、当前输出对应 GT、是否换成另一个 GT、是否当前输出没有达到定位门槛、是否缺少可验证历史。只有同时可验证前后身份的事件才能判断“同一身份接回 / 接到不同身份”。未定位、无历史和未输出应各自保留，不一概当成错误身份恢复，也不一概当成正确。

恢复很少时优先查看：缺失可信记忆、特征年龄过长、没有高分候选、几何门控、距离门限和行列歧义。当前低分候选没有外观特征，不能用零向量支持恢复。

若高分恢复已稳定有效，再安排低分 RGB 特征的独立提取与覆盖对照；只有 RGB 证据确实不足且有热红外可用性证据时，再进入 RGB/IR 联合身份编码。不能从当前配对 AUC 很高直接推导所有恢复会正确。

## 5. 检测覆盖决定后续是否应改检测侧

查看不同 IoU 门槛与候选池的覆盖差距：

- 全部缓存框覆盖也低：关联可用的空间受限，后续考虑检测器或有独立算力对照的轨迹引导局部重检测。
- 全部框较高、关联可用框低：重点检查置信度和候选使用规则。
- 关联可用框较高、出生可用框低：检查首次出现、出生延迟和生命周期约束。
- 原始框覆盖较高、跟踪仍丢失：回到关联竞争、输出定位和身份逻辑。

这些判断依赖检测框条件上界，不能宣称跟踪器绝对无法超过它；滤波、预测或新检测能够改变输出位置或候选集合。

## 6. 每次反馈建议提供

提供 `collect` 导出的目录，以及必要时的完整 ZIP。补充本地环境、代码提交、是否改参数、最值得看的序列与帧号。记录“哪个假设被支持、被否定或仍不确定”，再决定下一批最小实验。

本批不设置未经讨论的硬性 HOTA 增幅门槛，也不把小数点后微小差异称为显著改善。需要统计不确定性时，应按录制分组重采样并使用正确的合并统计，不能对 21 个序列 HOTA 的简单均值置信区间冒充整体 HOTA 的置信区间。
