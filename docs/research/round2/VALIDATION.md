## 2. 与第一批实现的兼容性

将当前 adapter 与结果提交中保留的第一批 adapter，在 120 帧确定性随机微小目标序列上并行比较。序列包含高分、低分和中断情况。原有四个变体的逐帧输出、ID、活动 / Lost 状态、均值和协方差逐元素一致。第二批新增策略通过新 variant 名或显式 CMC 模式启用。

原生无 ReID 工厂继续直接返回原生 BotSort；原生 RGB ReID 的缓存包装与直接原生实例在合成序列上的输出逐数组一致。真实数据运行仍将存档逐帧复现作为强制依赖：软件一致性测试不能代替用户原始数据的复现。

## 3. 端到端和统计口径

第二批集成测试使用 3 段生成图像，其中 1 段 calibration、2 段 evaluation；evaluation 包含一段空 GT。测试生成检测和特征缓存，不加载任何学习权重。

12 个几何 / 基线变体和 5 个外观变体，共 34 个 `variant × sequence`，依次执行：

1. 只使用 calibration 的离线外观门限拟合。
2. 在线缓存回放与 `--trace --output-trace`；预测进程启用 GT 读取限制。
3. 固定 TrackEval 的 HOTA / CLEAR / Identity 评估。
4. 对每个序列及合计，重新计算逐帧 CLEAR 事件并核对 FP / FN / IDSW。
5. 核对每条输出的检测索引、原始框、KF 框和实际 MOT 坐标。
6. 核对显式恢复事件确实发生，并运行新增恢复身份归因。
7. 对同输入的完整结果进行汇总。

此外，错误分析的 CLEAR 匹配与固定实现直接比较了 12 组、每组 35 帧的随机序列，覆盖空 GT / 空预测情况下的历史连续性细节。与正式指标不一致时诊断失败，不把另一种匹配规则得到的数字冒充 CLEAR。

## 4. 执行器的失败与继续语义

验证了以下实际风险：计划缺失控制配置、重复或循环依赖、源码/输入/配置快照变化、已完成输出被修改、任务失败留下部分输出、任务返回成功但没有产物、评价子集被用于控制参数选择、不同输入混合比较、部分结果冒充完整结果。

失败任务仅在显式 `--retry-failed` 时归档旧输出后重跑；已完成结果必须哈希复核后才跳过。导出校验计划哈希与已完成任务回执，只复制经过确认的实验和可选诊断。
