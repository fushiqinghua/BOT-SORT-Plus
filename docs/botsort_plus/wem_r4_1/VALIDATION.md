## 2. 理论到代码的对应

| 设计要求 | 实现与核验 |
| --- | --- |
| 在真实原生链路后接入 | 对固定 worker 和 adapter 源码校验 Git blob，插入正式预测后、GMC 后和原生最终整理位置；钩子集成测试实际驱动调用顺序 |
| 原生关联、B 和起轨优先 | 接入位置沿用旧 R4；只处理帧首已确认且仍未被常规更新的轨迹和未消费、未保留弱候选 |
| 弱框真实进入状态更新 | 复用原 R4 `transact`，对副本执行原生 `re_activate(..., new_id=False)`，通过最终整理后提交并进入后续帧 |
| 原 ID 与外观记忆约束 | 测试核对 ID、当前特征、平滑特征保持；弱观测不进入常规历史、不重充锚点预算 |
| 共同候选资格一致 | 所有策略保留锚点、几何、GMC、所有权、近重复和 top-5 规则；RGB 路径逐字段核对与 motion-only 路径的公共评分 |
| 沿用 W0–W3 固定机制 | 直接调用 R3.1 `evaluate_frame`；W2 不加绝对余弦或综合效用门，W3 保留无竞争／不可判／间隔不足的区别 |
| W_H 不消耗额外完整运行 | 每个在线组中只读计算 W_H，记录 W0→W_H→W1 的可行边和实际指派差值 |
| 关闭与观测模式不影响原状态 | 合成闭环验证 off/shadow/force_reject；真实数据还须由自动 smoke 对旧 R0 的轨迹、事件和逐帧状态摘要核验 |
| 不能用理论负结果阻止全量实验 | `full` 固定执行技术 smoke 后的十组完整跟踪和评测；不读取人工候选复核结果作为准入条件 |
| 指标相对正确参考计算 | 报告重新计算 BG 相对 BG_off 的差值，并以真实 `build_comparison` 接口测试防止误用 B_off 差值 |

## 3. 复核中处理的问题

- Windows 的已有运行锁不使用 `os.kill(pid, 0)` 判断进程存活，避免该平台上的终止进程语义；保守保留旧锁，确认原进程结束后再处理。POSIX 继续使用只读 signal-0 探测。
- TrackEval 源码摘要在启动前检查，避免十组跟踪完成后才发现评测器不是冻结版本。
- 新增的评分、决定、逐帧诊断 gzip 与弱事件流都列入逐序列摘要；shadow 与 force_reject 对这些流核对字节一致性。
- 已有完整实验臂必须输入、代码和所有输出摘要一致才可复用；无完成标记的中断臂先备份，不能静默覆盖。
- 固定协议的参数必须与实际 W0–W3 引擎定义一致，不能只修改文档参数而运行另一套机制。

## 4. 真实运行仍需完成的核验

本工作环境没有用户的完整图像、冻结检测与特征、原 R0 凭据、微调 ReID 权重和 GPU 运行环境，因此尚未执行真实十组实验、真实 BoxMOT 状态字节一致性或 Windows GPU 运行。

用户执行 `full` 时，程序会先运行两套参考的 off／shadow／force_reject 技术 smoke，随后完成十组各 30 段、12,590 帧的真实状态更新与 TrackEval。性能为零或下降不会被过滤掉，也不会阻止其他组的汇总。所有新性能结论应以该次完整输出为准。

官方 30 段此前已反复查看，按开发评测集解释。诊断日志与反事实计算有额外开销，本批耗时不直接代表精简部署版本的延迟。
