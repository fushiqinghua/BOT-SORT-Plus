## 2. 设计与代码的一致性

| 设计要求 | 实际接入 | 复核结论 |
| --- | --- | --- |
| BG_off、BG_W0 保持原策略 | 原 R4.1 observer 委托；完整复用产物经文件、输入、代码与范围校验 | 合成行为及事件一致性通过；本地真实参考仍由 `check`/smoke 核验 |
| lower_low 仅降低原生低分阈值 | 实例 `track_low_thresh=0.05`，W observer 关闭；缓存 GMC 保持冻结；运行协议明确有效阈值 | 实际拆分入口及协议测试通过 |
| relaxed_anchor 移除三项锚点支持条件 | 去掉 ready 与两项锚点 IoU 门；保留前一帧常规观测、预算、所有权、正式几何、一对一和最终整理保护 | 三类开放案例及保留限制均有测试；一次历史且 motion 不可算时仍可使用 W0 IoU |
| emit_only 输出真实弱观测支持的框，不反馈正式状态 | 在私有轨迹副本上执行 W0 更新预演；真实 tracker 走原生整理；完整原生 update 返回后才发布附加输出 | 当前私有测量输出一致、正式状态不变、未来原生演化一致的测试通过 |
| 明确状态摘要与对外预测的区别 | emit_only 的状态链使用原生输出；另记实际发布输出摘要及 weak_outputs_emitted / weak_state_updates | 状态漂移和非零正式弱更新会被拒绝；不把状态相同误写为 MOT 相同 |
| 一致全量比较，不根据收益决定是否运行 | 固定五组、每组 30 段 / 12,590 输入帧；仅技术完整性检查阻断；统一评测和归因 | 调度及报告测试通过；零干预、负收益正常进入报告 |

`emit_only` 的发布位置经过专门检查：原生 adapter 在最终整理之后还会记录输出、更新记忆。因此附加弱框不能直接从中间 finalizer 返回给该 adapter；本实现将其延后到完整原生 `update` 返回之后，避免弱输出被误计入正式状态。

锚点组是三个支持条件的组合消融，不能分别归因。输出组取消的是全部正式状态反馈，包括 KF 和轨迹生命周期，不能称为纯 KF 消融。全程候选和 B 恢复在不同策略间可以发生分叉；只要求其满足各自定义，不要求全部策略提交相同次数。
