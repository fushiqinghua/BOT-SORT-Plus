# TCO v0.1 数据、标签与运行契约

本文件规定后续本地实现必须遵守的数据边界。**当前提交未实现候选导出器、数据集、训练器或在线适配器；本文件中的记录格式与产物均为待实现契约。** 网络规格见 [MODULE_DESIGN.md](MODULE_DESIGN.md)，阶段安排见 [EXPERIMENT_PLAN.md](EXPERIMENT_PLAN.md)。

## 1. 三类数据必须分开

| 数据 | 包含内容 | 预测进程可读取？ |
|---|---|---|
| 运行输入与历史 | 当前原始检测、当前 RGB、帧前轨迹状态、过去真实观测 | 可以 |
| 离线标签 | GT 身份、定位 IoU、人工可见性判断、歧义与忽略标记 | 不可以 |
| 后验评价 | 未来 5／10 帧覆盖、身份持续、实际 FP/FN/IDSW、离线 oracle | 不可以 |

候选必须先由冻结运行的真实节点与边导出，再由独立进程附加标签。不能根据 GT 选择候选、移动搜索区、删掉坏历史，然后把这一输入分布称为在线可实现。

准备工具能够检查路径和少量 JSON 元数据；它不能证明上述隔离、图像正确性或数据无泄漏。相关核验属于 T0/T1 的真实实现工作。

## 2. 主键与坐标来源

每条成对记录使用以下主键：

```text
(run_fingerprint, sequence, frame, track_id, det_index)
```

`run_fingerprint` 区分参考、变体及配置。`frame` 统一记录原始跟踪帧号，并明确其基数与图像文件的映射；MOT 导出使用 1 起始帧号。`det_index` 是该帧进入跟踪器的原始检测数组中从 0 开始的行号，不能在阈值筛选后重新编号。若现有接口不能保留此关系，T0 先补只读索引映射。

同时记录 `source_video`、原始检测文件与特征文件摘要、图像文件摘要、解码尺寸、跟踪配置摘要和源码提交。不同运行的 `track_id` 数值相同不证明它们属于同一真实身份，跨运行比较只在离线使用明确 GT 锚点。

### 2.1 原始值与派生值

必须分别保存：

- `raw_xyxy`：当前检测原框，后续不可变。
- `pred_xyxy`：当帧 KF/GMC 之后、测量更新之前的预测框。
- `refined_xyxy`：特定 `(track_id, det_index)` 的建议框。
- `applied_xyxy`：最终用于本次测量的框；回退时逐值等于原框。
- `raw_score`、`raw_class`、原 RGB ReID 特征索引及缺失标记。
- `original_cost`、`guarded_cost`、`original_feasible`、`guard_allowed`、实际分配结果。

细化框不得原地覆盖共享检测数组。首版保留原检测裁块的 RGB ReID 特征；学习式空间头的表示保存在私有路径，不替换 B 或原生外观库的输入。

### 2.2 统一坐标

图像与检测统一为原图连续 `xyxy`，右下边界不含端点，不加 `+1`。保留 ROI 请求边界、图像有效交集、letterbox 缩放和 padding，使用同一正反变换。框边界与像素中心的变换分别核对，避免半像素偏差。

GT 保留评测定义下的原框；不得把 GT 裁到 ROI 或残差域来人为改善误差。预测框是否裁剪由原生输出链路决定，记录裁剪前后值。仅有“框看起来合法”的检查不足以代替图像边界、极小框、非方形 ROI 和 1 像素位移的坐标核验。

## 3. 真实历史与候选资格

历史最多 3 次，最远 12 帧，至少 2 次才能使用 TCO。每条历史必须满足 `history_frame < current_frame`，并携带真实原检测行与图像来源。高分、低分和 B 恢复后的实际观测可写入；纯预测、补框和其他运行的状态不可写入。

每帧开始时冻结私有历史快照；所有候选读取同一快照。帧末只追加实际被接受的原始测量来源。状态更新即使用了细化框，也不能用它替代原检测框成为下一次独立观测证据。运行时不利用 GT 清洗历史；训练侧把历史身份混杂作为实际输入分布保留。

首版处理原高分关联后剩余的已确认 `Tracked` 轨迹与原低分检测。它不处理 Lost 恢复、Unconfirmed 或新 ID。实际分数边界必须与固定代码中的比较符一致；协议中预期 `0.10 < score < 0.50` 需要 T0 核对。

### 3.1 两种闭环模式

| 模式 | 候选与配对的来源 | 可以变化的内容 |
|---|---|---|
| `fixed_pair_refine` | 每个运行自己的当前状态，经过原低分保护和匹配后实际接受的对 | 本次测量框；随后的真实状态与未来关联可自然变化 |
| `low_stage_pair_refine` | 原轨迹、原检测节点及原几何可行且原 guard 放行的边 | 这些边上的成对框及对应 IoU 代价，随后仍用原求解器和阈值 |

第一种模式不能照搬封存参考的未来配对。第二种模式不能复活原不可行边，也不能因为位置细化而绕过 `dual_low` 等保护。

若现有 guard 原地修改矩阵并累计日志，应在正常的一次调用中留存结果；只读采集不得额外调用它、改变计数器或污染状态。若无法还原原拒绝边，应先实现可核对的只读记录，不能猜测允许矩阵。

同一 `det_index` 在一个帧内最多消费一次。T3b 中多个轨迹可以对同一检测提出不同框，但 Hungarian 的检测节点仍是原索引。只有最终被选中的配对可以写状态。未消费检测以原始值进入原有候选池和 B 流程。

## 4. 离线标签：明确、否定与未知

每条记录分别保存历史身份可信度、当前可见性、候选对应关系和定位质量，不能压成一个笼统的“正／负”标志。

| 条件 | 支持监督 | 回归监督 | 质量监督 |
|---|---|---|---|
| 历史身份及当前目标位置明确，提名确属该身份 | 正 | 使用本身份真实 GT | 本身份的定位质量 |
| 可明确证明提名属于其他身份，或可靠标注／复核确认没有本目标 | 负 | 不回归到其他目标 | 身份条件质量为 0 |
| 历史污染、歧义、漏标可能、遮挡或当前对应关系无法确定 | 忽略 | 忽略 | 忽略 |

至少两个近期可核对观测指向同一 GT 身份、且其他已知历史不与之冲突，才可建立明确历史锚点。未知条目不能被线上删除；其标签仍保留未知。离线身份配对规则需登记类别、IoU 门限、重复检测、同帧多目标歧义和忽略区域处理。

高 IoU 的唯一 GT 对应可以作为自动标签来源；低 IoU 不自动意味着负例。定位不足但目标身份能够通过独立复核明确的样本，可获得正标签，必须注明标签来源。若难定位样本多数无法可靠标注，T1 应报告标签覆盖不足，而不是按最近 GT 自动补齐训练集。

共享质量头学习的是**身份条件定位质量**：身份明确正例取该框与历史锚定身份 GT 的 IoU，明确负例为 0，未知例掩码。不能取当前框对所有 GT 的最大 IoU，否则跟到旁边目标也会得到高质量标签。细化框的 IoU 标签和质量分支的取样坐标在该损失回传时停止梯度；不能让质量损失通过移动框改变监督目标。

E3 的“未匹配 GT”仅是评测事实。它可能包括定位不足、重复框、忽略对象、漏标或真实背景，不能整体作为负例。22 个人审案例只约束其明确复核的对象与帧段，不向整条轨迹或全部数据自动传播。

## 5. 划分、缓存与信息泄漏

正式新增划分名统一为 `fit`、`calibration`、`holdout`；holdout 不是可反复调参的数据。初始比例建议 70%／15%／15%，按母视频数量或预登记平衡规则分配，实际列表以 T1 审核为准。样本不足时应说明不可支持某个结论，不能切碎同一视频填满三组。

母视频映射使用有来源的显式清单；不能仅删除序列后缀推断。与官方开发测试集同源的视频不得进入新增头的训练或阈值选择。先固定分组再生成裁块，不能按帧、目标或裁块随机划分。

现有检测器与 ReID 的历史训练范围也要登记。新增 TCO 留出不能追溯性地证明整个系统从未见过这些图像。官方 30 段已多轮用于研发，报告为开发性评估。

缓存键至少包含图像来源、原检测与特征摘要、实际历史键、ROI 规格、标签协议、编码器版本、模型权重和运行配置。输入或模型变化后写新版本目录；不得保留旧推理缓存却只更新方法名。不同运行的帧前状态不同，不能直接复用参考的成对预测当作在线结果。

## 6. T1 可达性与 oracle 语义

报告以下分母，层层保留筛除原因：

1. 全部实际参考事件；
2. 原生低分节点／边与已配对事件；
3. 历史和 ROI 资格成立的事件；
4. 标签足够可靠、可以评价的事件；
5. 模型实际建议修正及最终采用的事件。

闭环误差减少必须在同一评价总体计算，未采用项按原策略计入。不能只在成功采用子集报告平均 IoU。

T1 的几何诊断必须区分：

- **GT 精确可达性**：GT 中心和尺度是否落在既定残差域；它不等价于所有可能跨过 IoU 0.5 的事件。
- **GT 引导可行修正**：简单限幅或有限网格找到的修正，是诊断参照，不是已证明的最大 IoU。
- **理想选择上界**：允许离线 GT 在固定候选支持中理想选择或定位，明确忽略图像是否可辨识、学习误差和在线选择限制。

有限数值搜索若没有严格界限证明，命名为“参考最优值”，不要命名为严格上界。所有 oracle 产物放在标签／诊断目录，不提供给正式预测进程。旧 D3 的 188/210 是特定恢复窗口中的历史结果，不是本轮全部 FN 的分布或 TCO 的预计修复数量。

## 7. 预期产物与状态

下列是后续实现产物约定，当前分支尚未生成：

| 产物 | 作用 |
|---|---|
| `pairs.runtime.jsonl.gz` | 不含 GT／未来信息的真实候选、历史和坐标 |
| `pairs.labels.jsonl.gz` | 通过主键联结的离线监督、可信度和忽略原因 |
| `split_manifest.json` | 母视频映射、fit/calibration/holdout 列表和来源 |
| `crop_manifest.json` | 图像与裁块变换、输入摘要和缓存版本 |
| `model_manifest.json` | 网络规格、训练来源、种子、权重及预算 |
| `calibration.json` | 工作点、选择准则、误用预算及数据指纹 |
| `changed_events.csv` | 实际采用、分配变化、后续持续与损伤 |
| `runtime_manifest.json` | 真正在线运行的源码、环境和耗时口径 |

准备工具生成的 `PREPARED_NOT_RUN` 只表示协议快照与任务账本已准备。手工改任务账本不等于软件通过，更不等于实验有效；每一阶段需分别记录实现状态、软件检查、真实运行、研究结论及证据位置。
