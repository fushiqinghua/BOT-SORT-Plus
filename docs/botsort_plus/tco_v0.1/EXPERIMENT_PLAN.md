# TCO v0.1 实验协议：从局部观测证据到闭环跟踪

版本：2026-11-27。起点提交：`235fe4097066b5023cc84ca8cd6edd5757fd658c`。建议工作分支：`research/vttiny-track-conditioned-observation`。

**本文件是待执行的实验设计。TCO 模型、采样器、训练入口和跟踪适配器尚需在本地实现；当前没有 TCO 的真实数据结果。** 本次分支中的准备、检查和状态工具用于整理协议与输入，不代表模型训练或跟踪实验已经实现。实际可执行命令以分支首页及运行说明列出的现有入口为准。

模块机制、张量和损失定义见 [MODULE_DESIGN.md](MODULE_DESIGN.md)。本协议确定实验次序、研究边界、比较方式及继续／停止条件，供本地 Codex 按阶段实现与复核。

## 1. 本轮要回答的问题

TCO 的假设是：**在有既定轨迹、当前存在真实检测提名的条件下，目标历史与当前局部图像能否提供额外信息，帮助判断和细化当前观测，并改善后续跟踪？**

首版先研究已有低分观测。原阈值之外的检测、无检测时的局部重检测、热红外补充均属于后置研究。这样可以分别判断新视觉信息、历史条件和改变观测集合的作用。

### 1.1 已有证据与本轮约束

| 已有证据 | 本轮由此采取的约束 |
|---|---|
| 第三轮中 B 补回 2,657 个原生漏检目标帧，G 补回 72 个，交集 19 个；联合保住并集的 99.19% | 不以大规模 B–GMC 冲突为默认前提；先寻找作用范围更广的观测问题 |
| 旧 D3 的 210 次恢复后首次中断中，188 次没有可用检测：95 次定位不足、89 次分数不在可用区间、4 次无检测行 | 统计首版能到达的具体事件；不能宣称 TCO v0.1 会处理全部 188 次，也不能推广成所有 FN 的比例 |

- 冻结 YOLO11-M RGB–T 检测权重、检测缓存及原始检测行编号、RGB ReID 权重和特征缓存、原生 KF、关联阈值、B 设置及参考运行中的 GMC／保护规则。

## 3. 数据划分与输入契约

### 3.1 母视频划分

使用官方训练来源数据建立 `fit`、`calibration`、`holdout` 三组母视频列表，目标比例按母视频数为 **70/15/15**。比例不是按帧数或裁块数随机拆分；母视频数量不能整除或需保持有效类别覆盖时，登记实际组数、事件数与偏差原因。T0 核验数据来源与母视频映射；T1 在样本导出前完成正式划分并冻结。具体约束如下：

1. 排除与官方测试视频同源的训练片段；同一母视频的全部片段只属于一个组。
2. 母视频映射来自显式清单与已核验来源，不通过删文件名后缀猜测。每个序列记录 `sequence`、`source_video`、官方划分和新用途。
3. 先锁定母视频列表、随机种子和文件哈希，再提取样本。不得按抽出的单帧或裁块随机划分训练／验证。
4. `fit` 拟合模型；`calibration` 选择支持、细化质量、质量增量三个采用阈值和检查点；`holdout` 一次性检验选定设置。中心与尺度残差限制是首版固定约束，不在本批校准中重新搜索。改变限幅需递增协议版本并重算 T1 可达性。留出验证失败后修改方案也应递增实验版本，并记录该组已经被查看。
5. 官方 30 段、12,590 帧已多次用于研发，始终称为开发性评估。TCO 的训练、阈值和检查点不得由这 30 段选择。另有真正未参与选择的数据时，单独登记最终留出结果。

现有检测器和 ReID 已按历史协议训练。本批新增的母视频留出主要约束 TCO 头和其规则，不能追溯性地宣称整个已冻结系统从未见过所有留出图像。

### 3.2 必备输入

| 输入 | 必备内容 | 使用阶段 |
|---|---|---|
| 冻结检测 | 每段每帧的原始框、分数、类别、原始行序号及协议 | 全部 |
| RGB ReID | 原始检测对应的特征、缺失标志、编码器与输入哈希 | 参考回放与闭环 |
| 原始 RGB 图像 | 与检测对应的真实解码帧及坐标尺寸 | T1 图像复核、T2、T3 |
| 参考运行 | 两个参考的预测、协议、可用的真实阶段事件、GMC 来源 | T0、T1、T3 |
| 训练 RGB GT | 帧、目标 ID、框、有效／忽略标志，及母视频映射 | 离线标签和评价 |
| 公开归档 | 第三轮汇总、D3、E1/E2/E3、③④⑤，作为来源 | 设计复核 |
| 可选 IR | 同步帧、坐标与局部对齐质量信息 | T4 后置扩展 |

公开目录没有完整原始事件流时，从已有服务器证据包恢复，或使用固定参考做只读采集。缺失检测索引时不以“最近框”或相等置信度猜配。若这些条件不满足，相应事件标记为 `unknown`，不能用于精确配对训练或归因。

### 3.3 事件单位与标签

所有线上可选边以 `(run_fingerprint, sequence, frame, track_id, det_index)` 唯一标识。跨运行预测 ID 不比较数值相等；离线通过官方 GT 与明确锚点对齐。历史条目必须满足 `history_frame < current_frame`。

每条样本至少保留以下信息：

- 当前阶段、帧前 track 状态、原始检测与预测框、原代价／可行性、原保护规则结果、参考分配结果、历史真实检测来源及缺失掩码；
- 裁块到原图的正反坐标变换、有效像素掩码、提名框掩码；
- 离线独立标签：旧身份锚点是否可确定、当前该身份是否有有效标注、当前提名与本身份／其他身份的重叠、可见性核对及忽略原因；
- 原始未处理值和各组件指纹，避免只保留处理后的张量而无法解释样本。

训练中的“无对应身份”包括明确的其他 GT 身份候选、可靠标注下已确认的无目标区域等。对可能漏标、严重跨模态可见性差异、旧身份未知、遮挡中但标注状态不清的条目，支持分支标签设为忽略；定位分支只在身份与位置明确时监督。**不将所有 GT 未匹配检测、所有低分框、所有低 IoU 框统一标成背景。**

正常匹配、错误提名、邻近同类目标、定位偏移、图像不足等均需保留。困难样本可在训练时过采样，但离线评价按真实队列分布或明确权重恢复；禁止用平衡后的训练样本比例报告部署精度。

## 6. T1：一次有限的错误分流与首版可达性核验

### 6.1 统一分流

先按第 3.1 节冻结 `T1/split_manifest.json`，再导出真实候选、运行侧记录和独立标签。来源映射或同源排除尚未核验时，停止训练采样，不以准备工具的路径检查代替划分核验。

对真实参考运行导出的事件，而非仅手工挑选的成功或失败案例，分成以下互斥主类，并保留次级属性：

| 主类 | 离线定义 | 首版可达性 |
|---|---|---|
| `eligible_low_pair_correct_control` | 原生低分已正确配对，历史足够，身份可核对，原提名定位准确 | T3a 可触及的正常控制，统计误修正与正确观测损失 |
| `eligible_low_pair_localization` | 属于原生低分已配对事件，历史足够，旧身份可核对，当前提名偏框 | T3a 的直接候选 |
| `eligible_low_edge_assignment` | 真实低分检测与轨迹处于原可行边，历史足够，正确候选未赢得分配 | T3b 候选；须进一步区分位置与身份代价原因 |
| `low_outside_original_edge` | 有低分框，但不在原几何可行边或被原保护拒绝 | 首版不处理，单列潜在扩展空间 |
| `score_out_of_band` | 有同目标重叠框，但不属于原低分范围，且当前未被正确输出 | 首版不处理；不能把它算成已能修复 |
| `no_usable_proposal` | 当前提名集合没有合格目标框 | 需要另行检验局部新观测，不并入首版收益上限 |
| `history_unavailable` | 无足够真实历史、历史间隔不合规或来源不可核对 | 回退原算法，单列覆盖损失 |
| `identity_or_visibility_unknown` | 无旧身份锚点、忽略区域、当前可见性／标注不清 | 未知，不用于硬判定或监督 |

主类顺序和判定程序要在导出器中固定，并记录原始布尔字段，使重叠条件可复算。例如一个分数不合格且历史不足的事件，要保留两个原因，而不能在不同报告中重复计入总数。

统计三个层次：全部参考事件、TCO 首版线上可达事件、其中可被离线 GT 可靠解释的事件。对已配对低分事件再按“原提名准确／偏框”“历史正确／身份混杂”“近邻竞争”“目标短边”分层。报告 `<8`、`8–<16`、`16–<32`、`≥32 px` 的原图尺度，避免将裁块缩放后的像素当作目标分辨率。

### 6.2 可达性、GT 引导参照与独立图像核对

在首版真实候选支持、原可行边、原 guard 及固定残差范围内，分别登记三类离线量：

1. **GT 精确可达性：** GT 中心与尺寸是否位于固定残差可行域中，并满足 ROI 和有效图像约束。它不能直接等同于所有能够跨过 IoU 0.50 的框数。
2. **GT 引导的可行修正：** 将 GT 残差投影至合法范围，或在有限网格中搜索一个较优框，记录其真实 IoU。找到合法有效框可以证明该例存在几何机会；搜索未找到不能证明无解。简单 clamp 和有限搜索结果只是参照，不是严格最大 IoU 上界。
3. **理想选择上界：** 固定候选支持后，允许离线 GT 理想选择身份／定位，明确说明忽略图像可辨别性等真实约束。它只描述潜在空间，不能作为可实现算法的指标。若声称约束域内严格 IoU 上界，须另外给出求解器、误差界与收敛依据。

独立人工图像核对用于判断当前图像和历史中是否存在可辨别支持，不将其称为数学上限。先从母视频、尺度、分流类型分层抽取有限图卡，保留抽样概率和完整队列分母。可先安排约 120–200 例核对，实际数量由队列大小和工作量登记，不能以挑出的图卡估计总体成功率。

图卡核对至少包含当前原区域、原始框、历史真实图块、邻近已标注对象和帧号。显示 GT 的离线解释视图和不显示 GT 的独立可见性判断分开保存。未知项允许保留；使用视觉模型建议时，模型建议和人工确认分列。

固定对齐的 GT 框、GT 搜索区域以及“最佳候选”只用于离线参照，不能传入训练采样的线上输入或正式 tracker。

### 6.3 T1 决策

- 有多个母视频上的可达偏框事件，且当前图像有目标支持：进入 T2。
- 正确候选多数存在、定位本来可用，主要是身份排名错误：将时序身份表征备选提为下一主线，另立方案；不将其包装为 TCO 定位成功。
- 空间主要在阈值外或没有检测，而原低分阶段几乎没有可达事件：记录 v0.1 范围不适配，先讨论有独立风险控制的新观测协议，不直接放开阈值。
- 目标信息不足或仅少数熟悉视频存在机会：判为 `INCONCLUSIVE` 或 `STOP`，保留证据，不继续盲训复杂网络。

必需产物：`T1/split_manifest.json`、`T1/episodes.jsonl.gz`、`T1/pairs.runtime.jsonl.gz`、`T1/pairs.labels.jsonl.gz`、`T1/reachability.csv`、`T1/T1_DECISION.md`。可补充 `T1/coverage_by_source_video.csv`、`T1/routing_summary.json`、`T1/review_sample.csv` 和 `T1/cards/`。历史 D3 的 188/210 仅作为动机对照，新的首版可达数量由本轮导出计算。

### 6.4 独立备选路线

`competition_conditioned_identity_representation` 的初始状态为 `RESERVED_NOT_IMPLEMENTED`。若 T1 显示跨视频存在“正确候选已在场、身份排序错误”的机会，或受控观测细化 pilot 无效，可另立时序身份表征设计，比较现有 ReID、当前图像头与轨迹到候选集合学习；须先核对竞争样本量和历史污染。它不是 T4，也不以 T3a 成功为前提；新设计与证据应单独归档。

## 7. T2：局部 RGB 头的最小验证

### 7.1 训练设置

首版使用 [模块设计](MODULE_DESIGN.md) 中的 `tco_small_conv_v1`：轻量共享 CNN，输入 RGB 与有效／提名掩码；当前区域 96×96，历史区域 64×64，最多 3 次历史、最多回看 12 帧、至少 2 次真实历史。中心每轴位移上限为原图 `min(3 px, 0.25 × 对应原框边长)`，宽高缩放在 `[0.8, 1.25]` 内。T1 的几何可达性与 GT 引导参照也须应用这些限制。具体张量、损失以模块设计和冻结配置为准。图块放大只是统一输入尺寸，不宣称恢复原图不存在的细节。

先用种子 `41` 完成一轮开发试验。取得留出增量后，固定超参数补充 `42`、`43`，检查模型训练随机性；不按开发 30 段选最好种子。每个比较臂使用同一事件队列、图像、采样预算和评价列表。当前图像臂也沿用相同历史资格条件，不能通过改变样本集合获得优势。

不把尚未核实的 RGB ReID 中间层直接写成已可用的冻结空间编码器。该适配器若后续实现，需要独立登记层名、权重、输出步长及坐标验证，作为编码器替换消融。

### 7.2 首轮比较臂

| 臂 | 内容 | 本轮作用 |
|---|---|---|
| `P0_raw` | 原始框与原策略，不训练 | 固定参考 |
| `P1_geometry` | 仅使用同一提名／预测／时间／分数等几何信息的小头 | 低成本信息对照，检验是否只是重新利用原数值 |
| `P2_current_rgb` | `current_repeat`：相同结构，历史像素槽使用当前候选裁块；无过去帧的外观信息 | 当前图像增量与分支容量控制 |
| `P3_history_rgb` | `causal_history`：当前局部 RGB 与真实过去观测 | 历史外观条件的独立增量 |

`P2_current_rgb` 与 `P3_history_rgb` 必须使用相同编码器、聚合器、头部、标量几何信息、样本、种子和优化预算，分别独立训练。P2 保留相同历史槽有效掩码及年龄元数据，将历史槽中的 RGB／像素与提名掩码替换为按模块设计构造的当前候选裁块；三份重复裁块共用同一图像变换，不能额外独立增强。不得删除历史分支，也不得只在训练好的 P3 推理时置零来冒充 P2。配置必须显式记录 `current_repeat` 或 `causal_history`。

`P1` 是一个局部预测对照，不重新搜索 Q/R，也不自动进入 30 段全量回放。训练预算在校准前锁定；正式比较不能为某个臂额外增加数据或反复调参。

局部信号出现后，再对**固定 P3 检查点**补充 `shuffled_history` 反事实诊断：使用其他轨迹的因果历史替换原历史，不引入未来帧，冻结样本、模型、阈值与替换规则并记录捐赠来源。它不是第五个训练臂，不重新拟合网络或选工作点；其分布变化须披露，结果用于辅助判断模型是否依赖身份历史，不能单独证明部署收益。

### 7.3 输出与校准

输出支持概率 `v`、共享质量评估器给出的原框质量 `q_raw` 与细化框质量 `q_ref`、框残差及建议框。采用细化需同时通过支持、细化质量和质量增量三个门槛。门槛只由 `calibration` 选择并冻结；未填写的 `null` 阈值不能解释为默认通过或允许直接上线。同时保存：

- 每条样本原框／细化框／实际采用框，以及回退原因；
- 支持分支的校准曲线与分组性能，定位分支的本身份 IoU、短边归一化中心误差；
- 在全部可达样本上的采用率、错误采用率、向上／向下跨越 IoU 0.50 的配对数量，以及邻近错误身份吸附；
- 原本正确提名被破坏的数量、原本错误提名得到修复的数量；
- 因历史、图像、身份标签缺失被排除的比例。

定位评价包含所有可达且标签可靠的条目，未采用修正的条目按原框计，不只报告被选择的成功子集。诊断可附 IoU 0.30/0.50/0.70，但完整 HOTA 仍按固定 TrackEval 阈值集合计算。

阈值校准应优先在固定错误采用预算下比较新增正确定位／观测支持。预算数值、分母和检查点选择规则在 T1、首次训练之前写入协议；先报告完整曲线，再解释锁定工作点，不以单个 AUC 作为上线依据。

### 7.4 继续／停止条件

进入 T3a 需要同时满足：

1. 相同验证队列上，`P3_history_rgb` 的实际采用框相对原框有净正确修复，原正确观测损失处于预登记容许范围；
2. 相对 `P2_current_rgb` 有可解释的历史条件增量，且不是只改善训练见过的一段场景；
3. 支持／定位分数在真实难例上能给出有用的采用排序，而非仅在容易正负样本上分离；
4. 补充种子和按母视频的配对统计没有显示结论仅由一次训练或一个视频支撑。

若只有 P2 有效而 P3 无增量，应把结果表述为局部观测细化，调整研究假设；不能继续称“时序条件”已经成立。若图像臂不优于几何臂，应停止当前表征／监督组合，先复核样本与信息来源。三种结果均允许归档，不以换网络规模自动延长试验。

必需产物：`T2/crop_manifest.json`、`T2/checkpoints/`、`T2/calibration.json`、`T2/offline_metrics.json`、`T2/T2_DECISION.md`。可补充 `T2/model_manifest.json`、`T2/training_history.csv`、`T2/offline_predictions.csv.gz`、`T2/paired_metrics.csv` 和固定模型的历史打乱诊断明细。

## 8. T3a：原低分配对后的闭环观测细化

`fixed_pair_refine` 的“固定配对”指**每个运行当前自身状态下，先执行原低分分配与保护规则，再细化已经接受的配对**。它不锁住历史参考在未来帧的匹配结果；细化影响 KF 后，后续状态、B 恢复次数和分配可能自然变化。

### 8.1 运行矩阵

| 组别 | 参考系统 | 观测处理 |
|---|---|---|
| A0 | `ref_B` | 原版 |
| A1 | `ref_B` | 选定 RGB TCO，`fixed_pair_refine` |
| A2 | `ref_BG`，实际为 `evidence_both` | 原版 |
| A3 | `ref_BG`，实际为 `evidence_both` | 同一 RGB TCO，`fixed_pair_refine` |

A0/A2 在来源和配置完全一致时复用已核验参考输出。A1/A3 是两组新的完整 30 段回放；不为两种参考分别在官方 30 段调阈值。先在训练侧留出视频完成闭环检查，再锁定设置执行开发 30 段。

TCO 的支持、细化质量和质量增量首版用于决定是否采用细化，未通过时回退原测量；不会自动删除原生已经接受的配对。若要验证拒绝观测，需要单独策略和消融，不能混入定位版本。

### 8.2 实施要求

- 原高分关联、未确认轨迹、新轨起始及原 guard 均按原流程执行。
- 已匹配低分检测的真实 `det_index`、原 score 和消费关系保持可追溯；细化只作用于该配对本次测量坐标。
- KF 的 F/Q/R、B 参数、原 ReID 向量和原 B 记忆写入规则冻结。TCO 私有历史从实际被接受的真实检测取得，保留原始来源；不能让预测框或别的运行的标签写入历史。
- 记录每次原框、细化框、采用框、KF 更新前后状态、下一帧对应关联、后续 B 事件。原检测特征未随细化重提取是有意的因素隔离，须在协议中写明；重提取特征属于另一个消融。
- 分别评价细化测量本身与 KF 更新后的输出框。测量 IoU 上升不保证输出 IoU 或后续身份上升，两者不得混为一项定位指标。
- 初次接入先做 TCO 关闭、只记录、强制回退的严格等价性；单帧坐标方向与尺度验证通过后再闭环。

### 8.3 归因与验收

同时报告两种配对：

1. **固定当前状态的局部测量对照**：用于解释当帧变化，不称为独立算法效果。
2. **真实闭环运行对照**：按序列、帧与 GT 配对输出，记录新覆盖、丢失覆盖、新增／消失 FP，以及后续身份变化。

重点检查细化是否让某条轨迹临时贴到邻近目标、错误状态是否经低分续接或 B 被延长、原正确配对是否在后续脱离。对端点可判定且窗口完整的事件，检查后 5／10 帧正确覆盖与原 ID 延续；视频尾部、未标注帧和身份歧义分别计为删失／未知，不计作成功。

若当前图像闭环增量与历史条件的贡献仍有疑问，只在相关参考上补 `P2_current_rgb` 消融。支持与质量的作用需要验证时，使用固定模型比较“正常采用”与“仅几何限幅、无学习质量采用规则”，同时报告正确观测损失；这不是另一轮阈值搜索。

通过的研究证据应包括 HOTA、IDF1／AssA 与真实覆盖的方向一致性，以及可解释的 FP 代价。MOTA 单项或 IDSW 减少不能替代这些条件。如果 HOTA/IDF1 不增且只是减少输出导致 IDSW 下降，判定未取得目标收益。

必需产物：`T3a/TCO_runtime_parity.json`、`T3a/trackers/`、`T3a/metrics/`、`T3a/changed_events.csv`、`T3a/followup_5_10.csv`、`T3a/T3a_DECISION.md`。跟踪与指标目录按 `<reference>/<variant>/` 区分来源，运行协议写入相应运行目录；汇总表保留 reference、variant 与运行指纹。可补充 `T3a/events/`、`T3a/paired_gt_changes.csv`、`T3a/refinement_effects.csv.gz` 等明细。

## 9. T3b：有条件地移到低分关联之前

只有 T3a 证明图像细化有用，且 T1 显示原低分可行边内存在足够的错误选择／未匹配机会，才实施 `low_stage_pair_refine`。

保持同一低分轨迹节点、真实检测节点和**原几何可行边集合**，在可行边上生成轨迹条件化的候选框，再计算其几何代价并做原一对一分配。原 guard 明确拒绝的边继续不可用；TCO 不复活该边，不扩大 Lost 池，不降低检测分数阈值，不新增公共 ID。

一个检测在不同轨迹边上可能得到不同细化框，但仍共享同一个原始 `det_index`，最终最多由一个轨迹消费。只有最终获选边的框可进入该轨迹更新；未获选边、影子历史和失败提名不写入真实轨迹。

最小比较为同一模型下的 `fixed_pair_refine` 与 `low_stage_pair_refine`。应报告：

- 候选与可行边是否符合预设不变量；
- 改变了多少行／列赢家、撤销了多少原正确匹配、增加了多少正确匹配；
- 有多少变化源于空间细化，有多少源于支持判定；
- 真实闭环指标及后续身份，而非只报告代价变化。

若改动分配极少，停止扩张这一阶段；若大量变化但正确与错误相抵，回到样本／目标函数分析，不自动加入更多门控。若要放宽原几何边，须形成新的协议版本，独立报告候选集合变化。

必需产物：`T3b/feasible_edges.jsonl.gz`、`T3b/guard_allowed_mask_audit.json`、`T3b/assignment_deltas.csv`、`T3b/metrics/`、`T3b/T3b_DECISION.md`。

## 10. T4：满足条件后单独登记的扩展

本阶段台账初态为 `PLANNED`，当前条件暂停。只有取得稳定的 RGB 闭环收益，且残余错误提供对应证据时，才选择一项扩展并建立新协议；不要求将下列各项全部实施。第 6.4 节的身份表征备选是独立研究路线，不属于本阶段。

| 扩展 | 必要证据 | 最小对照 | 尚未解决的风险 |
|---|---|---|---|
| RGB＋IR | RGB 失败事件中，IR 有可用且额外的信息 | RGB、RGB＋正确IR、错位／缺失IR；固定数据和预算 | 局部错位、热交叉、两模态标注不一一对应 |
| 受控扩边 | 原低分几何边之外存在可识别的正确候选 | 原可行边／新定义的受控边；单独核验新增边的 guard | 邻近身份吸附、候选竞争变化、保护规则被绕过 |
| 原阈值外观测 | 分数外目标在当前图像中可可靠区分 | 固定提名集合下的原策略／校准采用 | FP 增加、改变可用检测集合、隐式放宽出生 |
| 无框局部重检测 | 原图有目标但既有提名缺失，首版覆盖不足 | 有当前图像支持的局部重检测／纯预测对照 | 自我强化、重复输出、邻居吸附、真实不可见 |

每次只开启一个扩展。涉及新提名或原阈值外观测时，最终表中明确分为“固定原检测集合的跟踪改进”和“增加局部观测的完整系统改进”。不能把后者与固定检测对照混称相同输入条件。

条件满足并实际执行后的必需产物：`T4/extension_protocol.json`、`T4/seed_confirmation.csv`、`T4/ablation_summary.md`、`T4/thesis_claims.md`。尚未启动时保留暂停原因，不填造这些结果。

## 11. 统计、失败和停止条件

### 11.1 成对统计

以母视频为重采样单元，成对保留同一参考与变体。局部指标按事件做配对差值，并同时给事件加权与母视频分组结果；报告未知／删失分母。正式 HOTA/IDF1 的置信区间如计算，应在重采样后的序列集合上重算联合指标，不以逐序列 HOTA 的简单平均近似。若为降低成本只做局部统计区间，明确区间对应局部指标，不冠以“整体跟踪显著性”。

至少给出最主要贡献母视频剔除后的敏感性结果。该结果属于稳健性诊断，不能据此再选一个有利子集作主结果。多臂／多阈值探索的次数及模型选择过程全部登记，避免将最优一次当成预先确定的结果。

### 11.2 软件失败与研究结果分开

- 输入缺失、坐标错误、重复消费、未来信息、参考不一致：`BLOCKED` 或实现失败，修复后重做相应核验。
- 软件正确但作用空间不足：研究 `STOP`。
- 作用空间存在但当前模型没有可复现增量：研究 `INCONCLUSIVE` 或 `STOP_CURRENT_MODEL`，记录限制，不改写成已经有效。
- 离线改善但闭环退化：保留离线结果和传播链，判定尚未得到有效跟踪模块。
- 小幅单段提高、其他段无支持：按案例或探索性结果归档，不能宣称普遍收益。

T1 应填写期望覆盖范围、最大可接受的正确观测损失／FP 增量、训练预算和截止条件，在首次训练前冻结；不得看到 holdout 结果后再决定。数值依据项目实际队列和工作量登记；本文件不虚构一个通用的“提升多少点必然成功”门槛。

| I5 | 有证据时实现 `low_stage_pair_refine` | 原边集合与guard不变、影子不写回 | 阶段位置消融和机制解释 |
| I6 | 决定一个 T4 扩展或停止 | 新协议、独立因素、不同输入条件明确 | 后续研究版本或收尾结论 |

每个工作包完成后，必须在分支 README 补充实际存在的入口、完整参数示例、输入结构、失败退出码、输出清单及一条小规模执行路径。不要只提交空 `train.py`／`evaluate.py` 包装器或在文档中引用尚不存在的命令。

建议所有新运行写入独立的 `outputs/tco_v0_1/<experiment_id>/`，实验编号由本地配置给出。失败目录、源码快照、校准前协议和日志保留。重新运行生成新目录或显式的新实验版本，不覆盖已有证据。

### 最小回传证据

1. 输入与源码指纹、母视频划分、阶段状态和决定理由；
2. 各阶段完整分母、未知／删失数量、选中及被排除样本计数；

5. 恢复／中断后的 5／10 帧身份窗口、主要增益与主要损失案例；
6. 正常推理耗时和诊断采集耗时分开记录；

## 13. E3 并行收尾

E3 的现有 22 例可继续人工复核，作为背景／漏标／未知的证据补充。保留模型建议与人工标签的区别。它们是有限的诊断样例，不能直接当作足够规模的 TCO 训练集，也不能据此给全部 GT 未匹配条目赋背景标签。
