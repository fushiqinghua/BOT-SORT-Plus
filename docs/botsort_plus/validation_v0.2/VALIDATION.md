## 2. 与原 v0.1 的独立兼容验证

两个隔离 Python 子进程分别加载旧、新 overlay，运行相同的 60 帧确定性夹具。baseline、A、B、AB 共 240 个逐帧输出字节全部一致，关键 recovered/weak_birth 事件完整字段也一致。A 实际发生 18 次弱出生，B 实际发生 8 次恢复，AB 实际发生 18 次恢复与 3 次弱出生，比较不是无事件空跑。

详细输入与输出指纹见 `legacy_compatibility.json`；可复跑脚本在补丁根目录 `validation_scripts/check_legacy_compatibility.py`。

## 3. 有意义的机制检查

- 连续0.20弱检测，第5帧首次输出；前4帧不分配公开身份。
- 连续25帧0.11弱检测没有公开轨迹；几何稳定不代替检测支持。
- A 第一阶段通过后，后续低分和缺帧可导致复核失败；失败轮次不反复重用旧证据。
- A-only 面对仍有旧身份竞争的弱候选，不恢复也不新建；等待到期仍明确拒绝。
- B 第3次弱观测可先恢复；把 A 门槛提高至0.99也不阻止 B。
- 新版 A shadow 对原生、AB shadow 对 B_ref 的输出相等，包含重复高分与失败复核。
- 原生临时 Removed 仍留 lost 列表的边界行为得到兼容复现，B显式恢复资格仍独立过滤。
- 原生去重预检拒绝后，不消费候选、不写新身份记忆、不递增公开ID。
- 正式 start_frame 和 first_emitted 为当前提交帧，候选起点另外保存，不回填。
- 六组完整CLI软件回放通过缓存/原图尺寸检查、真实SOF、轨迹输出和结构审计。

## 4. 理论复核后的澄清和修正

复核修正了一项日志语义：新确认模式的旧 evidence 仅作池排序；legacy消融仍以其参与确认，故事件字段分别标记两种角色。

I 是保守准入，历史不一致只增加不确定性，不自动证明新身份。A的I仅约束弱来源出生；原生高分通道与B已有的规则保持独立。原生重复预检属于所有v2组的共同基座，不归为I专有收益。

基座枚举修复单独体现为 B_ref；不能将它的变化混入 A2 的算法收益。原12份配置继续选择legacy入口。

## 5. 验证的实际范围

图像和向量为明确标注的软件夹具，实际调用固定 BoxMOT、SOF、Kalman 和 TrackEval。**这些测试没有评估真实 VT-Tiny-MOT 的新 HOTA、IDF1 或误报收益。** 当前工作区缺少完整原始 RGB 视频帧与已验证真实特征缓存；用户侧需依照 A2_INTEGRATION 完成同输入回放。

补丁根目录的 `installation_validation.json` 另记录完整 baseline 副本上的新装、v0.1升级、回退、原文件不变与diff检查。它在最终清单生成后产生，避免安装结果记录与自身哈希循环引用。
