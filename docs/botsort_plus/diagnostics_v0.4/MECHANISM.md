# 四组诊断的机制与统计口径

## 1. 实现与理论的对应关系

| 设计要求 | 实现位置 | 约束 |
|---|---|---|
| 固定 B 参考、独立回放、先验证再分析 | `tools/run_botsort_diagnostics.py` | 两次独立子进程，检测、特征、配置、源码及解码图像身份一致；MOT 与原有事件逐字节一致 |
| 只读采集原生 KF/GMC 状态 | `botsort_plus/diagnostics/recorder.py`、`adapter_v2.py` | 复制状态，原生 SOF 每帧只执行一次；不改变关联与记忆更新 |
| 在线跟踪无 GT | `tools/run_botsort_plus.py` | 保留原有 GT 访问审计钩子；GT 只在预检及离线分析进程读入 |
| D1–D3 离线审计 | `botsort_plus/diagnostics/analysis.py`、`common.py` | 历史身份锚点来自之前已接受的真实检测，不用当前或未来 GT 反向修正锚点 |
| D4 全检测行与真实特征 | `botsort_plus/diagnostics/blur.py` | 核对冻结缓存、原图像素与 D1 来源；不生成替代 embedding |
| 原始数据不变、失败不覆盖 | 运行器及主入口 | 完整清单、SHA256、COMPLETE/FAILED 状态；新输出目录；分析异常保留记录 |

每个序列的帧编号为 1 开始的连续视频帧，空检测帧也必须记录。`det_index` 为当前帧原检测缓存的零基行号；这不是轨迹 ID。轨迹快照中的 `last_observation_det_index` 是最近一次真实观测的行号，可能来自更早的帧，不能当作本帧检测索引。

## 2. 记录四个边界

逐帧压缩记录采用 `botsort_motion_diagnostics_v1`：

| 字段 | 时间点与含义 |
|---|---|
| `before_prediction` | 本帧预测之前原生池的实际枚举结果；通常为活跃/Lost，原生清理过程中暂存的 Removed 也保留 |
| `after_prediction` | 原生 KF 预测之后、GMC 之前 |
| `after_gmc` | 原生 GMC 之后、任何本帧关联更新之前 |
| `unconfirmed` | 同时刻的原生待确认轨迹，单独记录 |
| `after_update` | 本帧更新及生命周期处理后，可追溯的活跃/Lost/本帧移除轨迹 |
| `detections` | 本帧所有检测的原行号、XYXY、分数及已有 RGB 特征有效性/质量 |
| `events` | 原有 `last_events` 的副本，含关联与 B 恢复检查/成功事件 |
| `output` | 本帧实际输出，包含 ID、检测索引与坐标，离线核对其与 MOT 文件一致 |
| `gmc` | 实际原生 warp、光流质量代理及不可判定状态 |
| `image_sha256`、`image_shape`、`image_dtype` | 实际进入跟踪器的解码 BGR 图像身份 |

状态为原生 XYWH 八维向量 `[cx, cy, w, h, vx, vy, vw, vh]`，并保存 8×8 状态协方差。`after_gmc` 额外保存原生投影均值与协方差。

**状态协方差 P 与投影协方差 S 含义不同。** 本实现的 `projected_covariance` 是 `S = H P H^T + R`，已包含观测噪声，不把它误写成只包含状态不确定性的 P。原生 Q/R 本来就有目标尺度相关规则，诊断没有把它们替换为常数，也没有调整任何噪声参数。

## 3. GT 配对与身份锚点

GT 采用仓库既有的 RGB MOT 格式、所有类别合并与去除零标记行的约定，类别/可见度只用于记录或分层。离线配对使用一对一 IoU 分配：默认阈值 0.5，并要求行/列竞争间隔至少 0.05；存在接近的竞争者时记为 `ambiguous`。未能唯一配对的检测或输出不会被强行赋予身份。

GT 身份编号允许从 0 开始；原生跟踪输出的轨迹 ID 从 1 开始。二者是独立编号空间，不能因数值相同就认定是同一身份。

这套标签只用于诊断。它不是 TrackEval 的连续性处理和官方 IDSW/FP/FN 统计，不能替换既有 HOTA、IDF1、MOTA 的评估器。

本帧预测对应哪个 GT，从该轨迹 `last_seen` 所指向的上一次已接受真实检测推断。如果那次观测无法唯一配对，则本帧锚点未知。当前关联错误也不会改变本帧已经采用的历史锚点，因此可以保留“预测错了/没有成功关联”的困难样本。它仍只是局部身份证据，不保证整条历史轨迹从未发生过 ID 混淆。

缺失 GT 表示当帧不可判定，不自动解释为目标不存在或跟踪失败。原始片段中的未标注、小目标 IoU 敏感性和人工 GT 噪声均会限制诊断可解释性。

## 4. D1：预测误差、检测误差与不确定性

对历史身份已知、当帧 GT 存在的预测，计算 GMC 后更新前的中心/宽高误差，并保留 GMC 前与更新后的误差。

中心误差的单位为原始 RGB 像素；归一化中心误差除以该 GT 框的短边。这样可以区分同样 3 像素偏移对 4 像素目标和 40 像素目标的不同含义。

关键列：

| 字段 | 含义 |
|---|---|
| `pred_center_error_px` | GMC 后、关联前的预测中心到历史身份对应 GT 的距离 |
| `pre_gmc_center_error_px` | 同一轨迹、同一帧、GMC 前的误差 |
| `gmc_error_change_px` | 后者被补偿后误差的变化：GMC 后减 GMC 前，负值表示该状态更接近 GT |
| `det_center_error_px` | 能唯一配对到同一 GT 的本帧检测误差；即使未被跟踪器消费也可统计 |
| `paired_prediction_minus_detection_error_px` | 同一 GT/同一帧的预测误差减检测误差，避免拿不同样本均值直接比较 |
| `gap_frames` | 距离上一次真实观测的帧数 |
| `det_available`、`usable_det_available` | 是否有足够重叠的检测，以及是否落在原生高/低分使用区间 |
| `accepted_identity` | 本帧实际接受的检测相对历史锚点为 same、different 或 unknown |

不确定性诊断分成两项：

1. `state_position_standardized_sq`：用 P 的中心 2×2 子块标准化预测中心与 GT 中心的误差，附二维 95% 椭圆覆盖标志。
2. `gt_paired_nis4`：同 GT 检测 `[cx,cy,w,h]` 与更新前投影均值之差，经 S 标准化得到四维 NIS，附四维 95% 覆盖标志。

95% 只是检查分布校准的参照，不是新加的关联门控。GT 噪声、非高斯误差、IoU 配对过滤及历史锚点选择都会影响覆盖率，不能看到覆盖不足就直接宣布某个 Q/R 缩放最优。矩阵不满足计算条件时留空，不悄悄修正协方差以制造数值。

二维和四维标准化平方误差的 95% 参照阈值分别为 `5.991464547` 和 `9.487729037`。检测使用区间严格遵循当前原生实现的 `score > track_high_thresh` 及 `track_low_thresh < score < track_high_thresh`；分数恰等于高阈值时不进入这两档。具体阈值读取本次协议中的 `native_config`。

## 5. D2：GMC 质量代理

记录原生 SOF 实际返回的仿射矩阵。为取得可解释的质量数据，观测器在复制的上一帧状态上重算确定性 LK 对应点，并使用**已经产生的原生 warp**计算残差。不会再拟合变换，也不会额外执行 RANSAC 或消耗其随机数。

原生 SOF 没有暴露 RANSAC 内点掩码，因此 `inlier_count_proxy`、`inlier_ratio_proxy` 都是残差代理，不能写成原生 RANSAC 的真实内点数。重投影残差、平移量换算回原始图像像素；旋转、尺度和覆盖范围按字段注明。

代理内点阈值为缩小图像中的 3 像素，即原图中的 `3 / scale`；当 `scale=0.15` 时是 20 原图像素。这是全局配准的一项粗质量描述，**较高代理内点率不代表小目标定位精度已经足够**。残差中位数/P90 基于全部 LK 成功点；`spatial_coverage` 是这些源点的包围矩形面积除以原图面积，不是网格覆盖率或真实背景覆盖率。

返回单位变换可能表示场景静止，也可能是原生内部拟合回退。无法从接口区分时记录 `identity_ambiguous`，不把所有单位变换算成 GMC 失败。第一帧初始化、点数不足等也单独记录。

`frame_error.csv` 保留逐帧代理、同状态补偿前后误差与各轨迹预测残差的分量中位数。后者是共同残差描述，可能混有目标共同运动，不能等同于相机位姿真值。

本轮没有执行独立的“关 GMC”跟踪消融。同一状态 GMC 前后对比只检验这一帧补偿的即时作用；相关性结果适合筛选假设，后续需真实干预实验验证。

## 6. D3：B 恢复端点与未来窗口

每个 `recovered` 事件先比较旧轨迹上次观测的 GT 与当前恢复检测的 GT，得到 `same_gt`、`different_gt` 或 `unknown`。`recovery_checks.csv` 另保留接受/拒绝原因、几何/外观成本及已有两观测提前恢复证据。

未来窗口严格为恢复帧 `t` **之后**的 `t+1...t+h`，h 为 3、5、10；恢复当帧不计入后续稳定率。每帧区分：

- 原 ID 正确延续。
- 相同 GT 由其他 ID 输出。
- 原 ID 错跟了其他 GT。
- 输出身份存在歧义。
- 缺少输出，但有可用检测 / 检测有歧义 / 没有可用检测。
- 该 GT 当帧未标注。

序列到末尾导致窗口不足时记为 `right_censored`。只有恢复端点为同 GT、未来帧数完整、该 GT 全程有标注、输出不含身份歧义的窗口，才进入完整窗口稳定率分母。未知和截断保留原始计数；分母为零返回 `null`。

“没有可用检测”仍可构成输出连续性中断，但其原因被单列，不能当成已经证实 KF 失效。应联查对应 `track_error.csv`，检查本帧预测、真实检测、原生关联阶段与竞争者。

上述 `missing_*` 表示没有取得可诊断地对应同 GT 的输出，既可能是轨迹进入 Lost，也可能是仍有输出但定位偏移到不足以配对。结合 `track_error.csv` 的 `state_after` 和原输出坐标才能区分两者。

## 7. D4：代理分层与人工真实模糊

逐行重新读取原图裁块，同时核对解码像素哈希、检测指纹、特征文件及元数据哈希、D1 审计文件来源。保留全部检测行，不只保留已经成功关联的轨迹。

质量代理包含原裁块尺寸、裁剪比例、灰度均值/对比度、梯度和拉普拉斯统计、方向一致性等。原缓存中的 `rgb_quality` 是已有未校准代理，单独记录；它和新代理都不是真实模糊概率。

RGB 外观使用缓存中真实且有效的单位向量：

- `same_gt_cosine_adjacent` 只在**真实相邻视频帧**、同一唯一 GT、两侧 embedding 有效时计算余弦距离。
- 跨空缺的同身份观测另记 `same_gt_cosine_across_gap` 与间隔，不冒充相邻帧。
- hard negative 使用同一上一帧身份锚点，对比当前帧其他唯一 GT 的有效特征，形成同锚点外观间隔。
- 特征缺失、身份歧义或没有合格负例时，对应值为空，不当作 0 距离或成功匹配。

自动分层和人工比较同时保留每项指标自己的有效样本数。人工 `clear` 与 `motion_blur` 比较按同序列、尺寸、分数、对比度、类别、可见度与遮挡控制；上一帧质量和标签也保留，以便检查外观距离两端同时退化的混杂。

人工样本是分层选择，比较仍是观察性分析。没有足够同层样本时返回“需要更多可比人工标签”，不填补假数据或自动推断真实模糊。检测器完全没有输出的目标不能从这些检测行恢复；若 D3 指向大量漏检，还需另做针对漏检帧的图像复核。

## 8. 下一步研究的边界

本次仅建设证据采集与分析，不改变原生 KF 的状态、Q/R、GMC、关联门控、ReID 记忆或 B 恢复逻辑。未来选择新模块时，应从出现频率、错误严重度、可修复性和额外计算代价共同判断。

仓库现有实验已经多次用于设计选择；在这些片段上继续诊断属于开发分析。后续验证应按原始视频分组，避免同源片段跨开发与验证集合，再进行冻结配置、独立模块和 B 组合消融。不要将这次诊断汇总当成新的盲测泛化结果。
