## 2. 冻结比较条件

### 2.1 两个主参考

- B：B_early_moderate。
- 当前联合参考：evidence_both。

evidence_both 包含相机选择之外的相关证据门控，不能将其解释为只比 B 多一个纯 GMC 因素。需要纯因素对照时，另列 B_early_moderate_dual_low 的完整配置与来源。

每个参考分别保留：

- 代码提交与未提交补丁；
- 检测协议、检测权重和缓存 fingerprint；
- ReID 权重、裁剪预处理和特征缓存 fingerprint；
- 跟踪配置与 GMC 配置；
- 输入序列、帧数和顺序；
- 原参考 MOT、事件、KF 状态链及其校验值；
- Python、NumPy、BoxMOT、检测框架版本。

路径存在、JSON 可读取、sha256 已计算分别是不同检查。计算出 hash 只有在与明确的预期对象比较后，才能称为来源一致。

### 2.2 v0.1 固定研究范围

- 当前真实检测，沿用旧 ID，不做弱起轨。
- 帧首 confirmed Tracked，原生、B 与起轨先处理。
- 第一来源 S0；S1 更低导出候选、S2 NMS 候选分别等待诊断。
- 最近 2–3 次常规 raw 观测验证当前一份弱观测。
- 每缺测片段最多一次弱更新；两帧常规确认后才可重置预算。
- 保留参考的原生 low 几何和 GMC guard。
- 原分数、原框保持不变，不改变 Q/R。
- 弱特征不写入长期模板或 B 记忆。
- 所有采样器、诊断代码和 W 不得在线读取 GT。

历史窗口和候选上限属于起始设计参数，学习阈值尚未冻结；在 R3 给出有效工作点之前，不允许把默认数值当作实验通过的工作点。

## 3. 批次 A：配置准备与 R1a 库存审计

### 3.1 所需输入

最低要求是现有逐序列检测 JSON 缓存及实际 low/high 阈值。缓存由 frames 数组保存帧号和每帧 Nx6 原始检测行。

这一步不需要：

- 图像或 GPU；
- GT；
- ReID 新推理；
- 修改原生追踪器；
- 重新导出检测。

先核对实际检测目录是否来自当前 RGB-T 主基线，不要误用旧 RGB 或其他权重的同名目录。

### 3.2 执行顺序

1. 按 LOCAL_RUNBOOK 创建本地配置，填写路径和参考位置。
2. 运行准备检查，解决缺失输入，不将“路径检查完成”写成“参考复现通过”。
3. 先选一个有代表性的序列验证缓存格式及产物。
4. 对冻结清单中的全部序列运行 R1a。
5. 核对序列、帧数、输入 hash 与既有缓存记录。
6. 按 RESULTS_TEMPLATE 记录结果，并保留完整审计产物。

初始发布的真实命令统一从 LOCAL_RUNBOOK 复制；本文件不提供尚未实现工具的伪命令。

### 3.3 R1a 核心计数

每个序列至少报告：

- 帧数与原始检测行数；
- 原生高分、原生低分行数；
- S0 行数和包含 S0 的帧数；
- high 边界遗漏等非 S0 情况；
- 原检测分数范围；
- 按原特征导出规则预期是否提取 RGB 的标记。

原生掩码要复现 float32 检测拼接整数行号后提升到 float64 的实际比较。不要按格式化小数比较，不要把 score=0.5 的高分边界漏洞混入 S0。

“按导出规则预期存在 ReID”不是实际特征有效性检查。即使满足导出规则，也不能据此认为裁剪有效、特征非零或具有身份区分能力。

### 3.4 当前工具产物

当前入口输出的具体字段以工具和 DATA_CONTRACT 为准，主要产物为：

| 文件 | 内容 |
| --- | --- |
| manifest.json | 输入文件、校验值、参数、执行范围 |
| summary.json | 库存级汇总及其解释边界 |
| per_sequence.csv | 逐序列库存计数 |
| s0_candidates.jsonl | 序列、帧号、原行号、原框、原分数及掩码来源 |

R1a 的研究状态应保持 **INVENTORY_ONLY_NOT_W_OPPORTUNITY**。S0 行数为零表示当前源未发现候选，不等于检测器所有更早阶段都没有响应。

### 3.5 批次 A 的回传内容

优先回传上述四个文件、本地配置的脱敏副本和简短执行记录。无需先上传全量图像、ReID 权重或视频。

回传说明写清：

- 实际检测源；
- 完整或子集运行；
- 是否修改阈值；
- 是否发现边界或格式异常；
- 是否有未纳入的序列；
- 接下来希望核查的来源 S0、S1 或 S2。

此时只做继续采样的安排，不发布 W 有收益的结论。

## 4. 批次 B：R0 采样一致性与 R1b 真实机会审计

**前置任务：I1、I2。当前需本地实现，未提供伪装成已运行的结果。**

### 4.1 新采样器应捕获什么

每帧至少保留：

- 帧首 active/confirmed 状态和旧 ID；
- 本帧正式 KF 的 selected/backup 预测及 GMC 信息；
- 原生 high/low 掩码和原始检测索引；
- 原生关联、B、起轨的当前更新与所有权；
- B 预留候选及其当前真实观测；
- 前 W 位置的轨迹状态；
- 常规 raw 观测历史和验证用来源；
- 最终输出与原检测索引的关联。

新采样器只读取状态，不提交 W，不增加候选到原始 dets，不更改 GMC 输入和 B 候选池。

### 4.2 先证明读取没有改变原流程

对两个参考分别运行关闭采样、开启只读采样和强制无采用模式。

先做固定小范围冒烟，再对冻结完整范围核对：

- 原 MOT 输出；
- 原有事件；
- 正式 KF 状态链；
- 原始输入 fingerprint；
- GMC 输入与输出；
- B 候选池及记忆的关键状态。

新诊断事件单独记录，不混入“原有事件相同”的比较。差异必须定位到确定原因，不能以“差别很小”直接通过。

### 4.3 线下身份与所有权解释

GT 只在采样完成后用于标记。先验证历史 raw 观测与参考输出的实际索引，再建立过去身份锚；不能用当前或未来成功匹配倒推历史锚必然正确。

当前候选区分：

- 已确认同身份；
- 明确其他身份；
- 有证据的背景；
- 未知、忽略或无法可靠判断。

候选来源、候选所有权、身份标记和几何可行性分别保存。候选“没被最终输出”不意味着没有被 B 预留。

### 4.4 机会统计

同时给出以下分母和筛选损失：

1. 全部帧首已确认活跃轨迹帧；
2. 经过原生/B 后仍没有观测的轨迹帧；
3. 具有有效常规历史的轨迹帧；
4. 有 S0 候选的轨迹帧；
5. 有合法、未占用且同身份候选的轨迹帧；
6. 对应 GT 当前尚未被参考输出覆盖的去重目标帧；
7. 缺测 episode、独立轨迹和来源组数量。

另外报告原本被其他身份覆盖、长 Lost、尚未起轨、几何不可达、锚无效和所有权冲突等情况。

**若第 4 项很多而第 5/6 项很少，说明库存丰富不代表新观测机会。**

## 5. 批次 C：R2 冻结状态下的观测价值

**前置任务：I3；依赖已验证的 R1b 输入。**

对每个可比较事件固定同一前决策状态，比较：

- 原 KF/GMC 预测框；
- 真实弱候选原框；
- 在状态副本上执行原 KF 更新后的后验框；
- GT 辅助选择且满足所有权、重复组、一对一约束的候选结果。

使用 same-ID IoU、中心误差、评价阈值两侧的改善/损伤计数；区分 raw 框价值与 KF 吸收之后的价值。

GT 辅助选择不能改变候选坐标，不能允许多个轨迹同时使用同一候选，也不能将未来轨迹信息带入当前选择。其结果只描述“当前候选集合受约束可达机会”，不能称为完整跟踪收益上限。

按 source、目标尺寸、密度、GMC 状态、序列/来源组分层，检查是否被单一轨迹支配。top-k 比较 1/5/10 个组时，要记录裁剪前后召回和潜在竞争遗漏。

### 继续或停止

- 候选本身几乎没有优于预测的定位信息：坐标更新部分暂缓。
- 候选能提供存在/身份信息，但定位无增量：保留 W-coast 验证路线。
- 机会主要是长 Lost 或两帧以上缺测：重新评估 W v0.1 的范围，不能悄悄扩大资格。
- S0 缺少机会而更早检测输出可能保留信息：另立 S1/S2 有界审计。

不预设任意收益百分点作为理论保证。最低有用机会规模应在看完整开发结果前，结合计算成本与误接预算登记。

## 6. 批次 D：R3 身份、背景与准入校准

**前置任务：I4；不能用官方 30 段反复选门槛后宣称独立泛化。**

### 6.1 分组与标签

优先按母视频隔离拟合、校准和留出。缺少可靠母视频映射时，采用可解释的代理分组，并保留相关性限制。无相同图像 hash 只表示没有发现字节相同帧。

补充困难身份标签时记录 human_review_status。模型辅助意见不能直接变成人工确认；未知样本单独报告，不默认为背景。

### 6.2 相同输入上的对照

候选池、前决策状态、原生几何条件、候选预算一致，比较：

1. 普通 IoU / 原分数；
2. 复合相似性或分数提升参考；
3. 真实历史运动与外观；
4. 加入双向竞争后的完整准入；
5. 外观不可用时的几何唯一子集，单独计账。

只复用论文某组件时写“组件参考”，不标为完整 TrackTrack 或 BoostTrack++ 复现。

### 6.3 验收内容

在校准前登记错误身份与背景接纳预算、主指标、有限阈值网格和主比较组。记录：

- 正确接纳 / 已知正例；
- 其他身份接纳 / 已知其他身份；
- 背景接纳 / 已知背景；
- 未知接纳数；
- 外观有效覆盖率及独立身份、来源组数量；
- 固定误接预算下的正确覆盖。

保留“拒绝全部”的合法工作点。如果预算内没有有用覆盖，不生成线上启用配置。

少量样本零误接不代表已证明零错误率。报告计数、分母、组间差异和不确定性；相关视频帧不能作为大量独立试验。

## 7. 批次 E：R4 有条件闭环

**前置任务：I5–I7，且 R1–R3 决策支持。**

### 7.1 首批对照

| 实验组 | 改变 | 解释目的 |
| --- | --- | --- |
| B 与 evidence_both | 参考复现 | 固定基线及完整开关 |
| 直接下调 low | high/birth 不变 | 阈值改变是否已足够 |
| 同旁路池普通补接 | 保留来源与优先权 | 候选来源本身的作用 |
| Coast-only | 不读当前弱候选，只延续预测 | 单纯多保留一帧的作用 |
| W-coast | 使用 W 准入，跳过量测更新 | 弱证据存在/身份准入的作用 |
| 完整 W | 用被准入的原始弱框更新 KF | 坐标量测更新的额外作用 |
| B+W、evidence_both+W | 分别组合 | W 与已有方法的联合增量 |

直接下调 low 会改变 B 的输入时机，这是该对照的实际行为。它与保持原生输入的旁路补接要分别报告。

### 7.2 预测延续对照的准确归因

两个 coast 对照都不能调用 update(predicted_box)，因为零残差仍可能使协方差收缩。它们跳过 measurement update，输出来源记为 prediction，真实观测时间与预测输出时间分别记录。

闭环状态会分叉，不能宣称组间始终只差一个框坐标。R2 承担严格的当前状态对照。

- W-coast 优于 Coast-only：支持当前弱证据的准入价值。
- 完整 W 进一步优于 W-coast：支持吸收候选坐标的增量。
- W 与 W-coast 相当：不能据此否定所有弱证据，只能说当前坐标更新没有显示额外收益。
- 各组与 Coast-only 相当：缺少弱证据的独立增量支持。

### 7.3 主要指标与组合归因

报告 HOTA、IDF1、AssA、DetA、FP、FN、IDSW、Frag、逐序列变化和开销，并说明评估器、尺度和汇总方法。

逐事件归因至少包括：

- W 新增覆盖与损坏的原有覆盖；
- 原先由 B 恢复、现在由 W 提前续接；
- B 原有效恢复机会是否被破坏；
- W 导致的错误身份或漂移链；
- 被最终去重回退的提案；
- 所有权/锚点/竞争/预算各拒绝原因。

B 恢复次数下降可能意味着 W 提前解决，也可能意味着 W 干扰了 B，不能仅按次数判断。

### 7.4 仅在完整方法有效后做必要消融

依次选择有具体疑问的消融，不一开始展开大网格：

- 去邻轨竞争；
- 去历史外观或历史趋势；
- S0、S0+S1、S2 来源分解；
- 弱更新上限 1 对有限 2；
- 可信锚隔离与重置；
- ReID 提取数量、候选预算、额外延迟。

若主要增益仅来自个别轨迹，或新增 FP/IDSW 抵消收益，应停止或重构，不能靠不断增加阈值搜索把开发集调成正数。

## 8. 阶段决策与回传规则

每阶段填写 [RESULTS_TEMPLATE.md](RESULTS_TEMPLATE.md)，使用以下状态区分事实：

- NOT_RUN：未执行。
- IMPLEMENTATION_PENDING：相关工具尚未实现。
- INPUT_CHECKED：完成明确列出的输入检查，不代表科研验收。
- INVENTORY_ONLY_NOT_W_OPPORTUNITY：完成 S0 库存。
- SOFTWARE_PARITY_PASSED：仅新代码一致性通过。
- EVIDENCE_READY_FOR_REVIEW：有可复核诊断，尚未决定继续。
- CONTINUE / REVISE / STOP：由证据支持的研究决策，并附理由。

不以目录已创建、脚本退出 0 或文件存在自动产生 CONTINUE。真实结果保留原始失败与未知项，不用 0 填写未运行指标。

最先回传批次 A 的结果；若需要本地编码，按 IMPLEMENTATION_TASKS 的 I1–I4 顺序推进，避免越过证据直接完成在线 W 后才发现候选源没有机会。
